# Phase 1.1 — units, engineering presentation and validation

## Cause and correction

The old `Reservoir input units` selector converted setup widgets, while the
`PVT file units` and `History file units` selectors controlled import parsing
only. Previews rendered the source DataFrames directly. Bundled files bypassed
file selectors and were correctly parsed as SI, but were still shown as raw SI
beside a selector that could say FIELD. Results, charts, CSVs and the primary
inspector then rendered canonical SI fields directly. This was a display and
labeling inconsistency, not a change to the calculation engine's unit basis.

The corrected path is:

```text
uploaded-file units → canonical SI inputs → unchanged engineering engine
                                              ↓
                                       canonical SI state
                                              ↓
                                project/display units and labels
```

Setup widgets also convert through a separate canonical SI draft. Changing the
project display units rebuilds widgets from that draft, preserving edits. Saved
simulation objects are read-only inputs to the new presentation functions.
An SI file still uses Pa; an SI engineering view uses MPa. Bundled examples are
always parsed as SI, then displayed in the selected project units; the inactive
uploaded-file selectors are clearly disabled.

| Quantity | Canonical SI | SI display | FIELD display |
|---|---|---|---|
| Pressure | Pa absolute | MPa | psia |
| Oil volume | stock-tank m³ | stock-tank m³ | STB |
| Water volume | surface m³ | surface m³ | bbl |
| Gas volume | standard m³ | standard m³ | scf |
| Withdrawal/support/residual volume | reservoir m³ | reservoir m³ | rb |
| Bo, Bw, Bwinj | m³/m³ | m³/m³ | rb/STB |
| Bg, Bginj | m³/m³ | m³/m³ | rb/scf |
| Rs | m³/m³ | m³/m³ | scf/STB |
| Expansion per original oil volume | m³/m³ | m³/m³ | rb/STB |
| Compressibility | 1/Pa | 1/MPa | 1/psi |
| Viscosity | Pa·s | Pa·s | cP |

Numerical table formatting retains eight significant digits and uses scientific
notation for small quantities. Engineering datasets retain full floating-point
values with readable unit-bearing headers. The inspector's mixed text/numeric
table formats values for human reading; full numeric state remains available in
the advanced output. Original import templates keep their documented schemas
and are explicitly labeled SI/Pa.

The primary residual chart shows `abs(R) / max(abs(Fnet), 1 reservoir m³)`.
Its zero-based axis includes the 1e-8 PASS boundary so machine roundoff is not
visually inflated. Values are not clipped or replaced by an artificial epsilon.
PASS is ≤ 1e-8; WARNING is > 1e-8 through 1e-5; FAIL is > 1e-5 or a failed solve.
These are presentation categories: the original solver still requires both
absolute residual ≤ 1e-5 reservoir m³ and relative residual ≤ 1e-8.

## Independent hand benchmark

The fixed inputs and expected outputs are committed in
[`tests/fixtures/volumetric_hand_case.json`](../tests/fixtures/volumetric_hand_case.json).
Expected values are literal hand-calculated numbers; no expected term is
generated by calling the engineering implementation under test.

Tank: initial date 2020-01-01, Pi = 30 MPa, N = 100,000 stock-tank m³,
Swc = 0.2, m = 0, cf = 0, cw = 0. This isolates volumetric oil expansion while
retaining separate produced gas/water and injected gas/water terms. No aquifer.

| Pressure (MPa) | Bo (m³/m³) | Rs (m³/m³) | Bg (m³/m³) | Bw (m³/m³) | Bwinj (m³/m³) | Bginj (m³/m³) |
|---|---|---|---|---|---|---|
| 10 | 1.30 | 80 | 0.012 | 1.04 | 1.00 | 0.010 |
| 20 | 1.25 | 80 | 0.006 | 1.02 | 1.00 | 0.005 |
| 30 (initial) | 1.20 | 80 | 0.004 | 1.00 | 1.00 | 0.004 |

History is zero at the initial date. At 2021-01-01:

| Quantity | Surface cumulative value |
|---|---|
| Np | 4,000 stock-tank oil m³ |
| Gp | 340,000 standard gas m³ |
| Wp | 100 water m³ |
| Winj | 200 water m³ |
| Ginj | 4,400 standard gas m³ |

At the independently selected target pressure of **20 MPa**:

```text
Eo  = (1.25 - 1.20) + (80 - 80) × 0.006 = 0.05
Eg  = 1.20 × (0.006 / 0.004 - 1)        = 0.60
mEg = 0 × 0.60                         = 0
Efw = 0                               (cf = cw = 0)
Et  = 0.05 + 0 + 0                     = 0.05

Fprod = 4,000 × 1.25
      + (340,000 - 4,000 × 80) × 0.006
      + 100 × 1.02
      = 5,000 + 120 + 102              = 5,222 reservoir m³

Water injection support = 200 × 1.00   = 200 reservoir m³
Gas injection support   = 4,400 × .005 = 22 reservoir m³
Combined injection support             = 222 reservoir m³
Fnet = 5,222 - 200 - 22                = 5,000 reservoir m³

N × Eo  = 100,000 × 0.05               = 5,000 reservoir m³
N × mEg = 0
N × Efw = 0
N × Et  = 100,000 × 0.05               = 5,000 reservoir m³
Residual = Fnet - N × Et               = 0
```

Eg is unweighted expansion; m = 0 removes its support contribution. The automated
tests evaluate closure at the independently prescribed pressure and separately
run the pressure solver to recover it, checking every fixture term.

Observed implementation results:

| Check | Expected | Actual |
|---|---|---|
| Calculated pressure | 20 MPa | 20 MPa |
| Fprod | 5,222 reservoir m³ | 5,222 reservoir m³ |
| Water/gas injection support | 200 / 22 reservoir m³ | 200 / 22 reservoir m³ |
| Fnet | 5,000 reservoir m³ | 5,000 reservoir m³ |
| N × Et | 5,000 reservoir m³ | 5,000.000000000005 reservoir m³ |
| Signed residual | 0 | −4.547473508864641e-12 reservoir m³ |
| Absolute relative residual | 0 | 9.094947017729283e-16 |

The tiny residual is floating-point representation error, well below acceptance.
The earlier combined gas-cap/compressibility/injection benchmark remains intact.

## Verification

On Python 3.12.10, the full suite passes **136 tests**: all 88 original tests
plus 48 new cases. Existing tests were retained; two new UI regressions were
appended to `tests/test_app.py`. New coverage includes:

- 30 MPa = approximately 4,351.1321319 psia and the specific PVT display regression.
- Both display systems round-trip pressure, oil/water/gas/reservoir volume,
  Bo, Bw, Bg, Rs, compressibility and optional injection FVFs.
- Six-step equivalent FIELD and SI inputs produce the same canonical pressure,
  cumulative quantities, increments, PVT properties and balance terms within
  stated floating-point tolerances (pressure within 0.01 Pa).
- Display adapters and UI unit switching leave saved canonical states unchanged.
- Edited setup values survive display-unit switches.
- Pressure observations and predictions use exactly the same plot conversion.
- Results, exports and inspector dimensions agree, and raw outputs stay advanced.
- QC boundary categories and the tolerance-scaled chart handle zero/tiny residuals.
- The independent hand benchmark verifies every expected term and recovers pressure.

The six-step bundled example's entire serialized canonical `SimulationResult`
was compared with a snapshot captured before this pass and was **exactly
unchanged**, including solver diagnostics. Its maximum absolute residual is
**2.051820047199726e-9 reservoir m³** and maximum absolute relative residual is
**3.3030993625369126e-14**.

SHA-256 comparisons also confirmed that every file in `domain/`, `pvt/`, `mbe/`
and `solver/` is unchanged. `units/conversions.py` and the original file-import
contract were not edited. No additional reservoir physics was introduced.

Reproduce:

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
.\.venv\Scripts\python.exe examples/run_example.py
```

The cache provider is disabled only to avoid a pre-existing Windows permission
issue in `.pytest_cache`; no tests are skipped or filtered.
